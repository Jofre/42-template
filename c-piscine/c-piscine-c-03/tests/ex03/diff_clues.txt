  n bounds the SOURCE here, not the result -- which is the trap. The
  destination is printed after the call, then 1 or 0 for the return; its
  buffer is filled with ff bytes past the old terminator, so ff bytes at the
  end of the result are a terminator that was never written.
    * n == 0 diverges                    -> nothing is appended, but something
                                            still has to be true of the result
    * n larger than the source           -> the terminator stops it before n does
    * the result is one byte long        -> counting the destination's own
                                            length against n
    * the result is unterminated         -> the terminator is always written,
                                            whatever n was
    * only inputs holding a byte of 0x80 or more -> whether a comparison in
                                          your loop sees that char as negative
