# conventions: no byte family -- the items reach only the harness's own functions, never the code under test
  The order of the visits IS the answer.
    * an empty tree           -> a NULL root: what does your function read
                                 before it checks for one?
    * a leaf                  -> both children are empty, and neither may be
                                 followed
    * the root appears in the wrong place -> prefix names WHEN the node itself
                                 is visited, relative to its two subtrees
    * left and right swapped  -> the order the two subtrees are taken in
